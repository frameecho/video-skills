# 参考视频驱动的代码 MV

交付可重现的源码、完整成片、参考对照和可核查的验证结果。画面使用 Canvas、SVG、WebGL 或适合项目的代码图形。模型、画风、比例和时长服从用户选择；用户指定 Claude 负责核心生成时，保留其生成记录，协调助手负责准备上下文和验收。

## 工作流程

1. 检查音频时长、参考视频和歌词时间文件。区分整首与片段、用户目标与参考中的偶然元素。缺少输入只询问会影响结果的内容。
2. 读取 [参考分析](references/reference-analysis.md)，抽取全片代表帧并分析真正的视觉结构。此前的风格约定若与新参考冲突，以最新用户要求为准。
3. 将分析与输入路径交给 Claude。读取 [Claude 协作](references/claude-workflow.md)，使用其中的任务模板。用户要求自主完成时，自行进行中间检查，不强制要求逐阶段确认。
4. 先渲染几个能检验风格的代表镜头，与参考并排检查。素材来源、画面媒介、构图密度、字体尺度和镜头运动一致后再推进整曲。只换调色不能算匹配风格。
5. 阅读 [渲染与验收](references/render-and-qa.md)，完成整曲、全片解码、时长和音轨检查。自动检查不能替代观看开头、中段、高潮、转场和结尾。

## 实现约定

- 让画面函数由时间 `t` 确定；固定随机种子，不依赖现实时间、网络资源或播放状态。可缓存静态纹理。
- 按歌曲结构安排镜头，不预设固定镜头数或每镜时长。不要把整曲做成同一个循环画面。
- LRC 通常只有句级时间；句内均分的逐字高亮应标为插值。RMS/FFT 响应不等于节拍或强制对齐。
- 将画面来源记录为代码绘制、用户素材、外部素材等实际类别。没有生图/生视频才可这样说明，不得把找来的素材说成全部代码生成。
- 参考视频中的桌面、终端、窗口可能就是主要设计语言；不要一律当作水印删掉。平台账号、水印和他人专属标识另行处理，不照搬。

## 可用资源

- `scripts/inspect_media.py`：ffprobe 元数据和按时间取帧。
- `scripts/render_canvas.cjs`：本地 HTML 的确定性逐帧渲染，包含可选音轨；输出清单检查完整度。
- `scripts/validate_video.py`：全片解码、帧数/时长/音轨/格式与黑场检查。
- `assets/scene.html`：无版权歌曲或外部依赖的最小 Canvas 示例。仅演示接口，不是成片审美模板。

最后报告生成者、素材来源、时间对齐方式、视频规格、检查结果和剩余限制。上传成片、发社交平台或公开源码只在用户授权范围内执行。
