# Claude 核心生成

先检查本机 `claude --version`、当前认证与工作目录。不要读取或输出认证文件。CLI 参数以本机 `claude --help` 为准；不在 Skill 中固定某一版本或付费模型。首次试跑使用小任务确认可写入项目。不要开启跳过权限检查的模式。

把以下模板保存到独立工作目录的 `PROMPT.md` 并替换方括号字段。让 Claude 直接读取本地媒体和提取帧，不要仅转述“参考这种感觉”。

```text
你负责本项目的核心视觉分析、分镜和代码实现。
输入：音频[路径]，参考视频[路径]，代表帧[路径]，歌词时间[路径/缺失]。
目标：[画幅/分辨率/帧率]，覆盖[整曲或区间]。
用户创作授权：[自主决定画风细节、叙事、镜头与节奏/需要讨论的事项]。

先独立分析参考的媒介、构图、字体尺度、材质和运动，写 style-analysis.md，
区分视觉主体与账号水印。不要沿用和新参考冲突的旧画风。
用原创代码绘制，不调用生图/生视频，除非用户另有指定。
按音乐结构规划叙事，不强制固定镜头数量。

先实现可以对照参考的代表镜头并渲染样片，自检后继续完整作品。
采用可确定性求值的 renderFrame(t)，声明画布尺寸和资源加载就绪条件。
不要依赖页面播放、现实时间或不固定的随机数。
模块化实现场景、角色、歌词和镜头运动，及时保存可运行代码。
LRC 是句级时间；插值高亮不能标为精确逐字对齐。
记录素材来源、生成工具、假设和仍未验证的项目。
完成源码、整曲成片及检查结果；不要发布到外部平台。
```

可使用 `claude -p < PROMPT.md > claude-output.txt`，结合本机支持的工作目录/工具权限参数。先让小模块可运行，再逐步补齐，避免一次输出巨型文件导致长时间没有可检验结果。日志留在工作目录，不进公共仓库。

协调助手可运行渲染和修复基础设施；如果用户要求核心由 Claude 完成，画面/分镜偏离应交回 Claude 修改，不能悄悄换成协调助手重画并保留 Claude 署名。最终说明以实际调用及文件产物为依据。
